# V0.4 使用与演示步骤

## 一、首次启动

双击“启动平台.bat”，或在项目目录运行 `python serve.py`。浏览器默认打开127.0.0.1:8765。需要Python 3.10或以上，不用安装第三方包。不下载模型，不使用GPU。程序占据当前控制台，Ctrl+C可停止。

直接双击index.html也可使用非联网功能。参考地图为本地文件，设备拓扑来自你绑定的数据，不依赖在线瓦片。

## 二、不填API的演示路线

1. 动态建模页选择L1。中文题干进入“需求与条件确认”。
2. 核对每条内容与来源，分别点击“保存并确认”；再点击“确认全部条件并继续”。
3. 点击“加载演示模板”。这里是人工模板，不是API生成；会在界面和导出中保留标识。
4. 在“方程确认”切换数学模型、变量、目标、约束、代码等分区。逐项确认或退回。可填审核备注。
5. 修改一条目标或约束并保存，会产生新版本；比较版本查看差异。新版本不会继承原确认。
6. 在“校验与修正”执行静态规则检查。查看来源、需求关联、参数线索、单位和代码占位等问题。物理验证与求解显示未执行。
7. 风险页点击“加载接口演示意见”，选择接受/拒绝，再将接受意见纳入候选新版本。演示来源继续保留。
8. 导出模型、静态报告或“求解前建模交接包”。这些不是求解结果。

## 三、填写真实模型API后

在服务设置中填写API基础地址、对话路径、模型标识和密钥，点击保存。可先测试最小请求，注意可能产生计费。使用标准Chat Completions兼容服务。若服务不支持response_format，选择“提示词约束JSON”。不支持该协议的服务需按契约增加适配。

模型生成前必须确认需求条件。“API提取条件”可从自然语言生成清单；仍要用户核对。选择“课题2提供的模型API”可改走课题2入口。

默认不发送完整电网数据。勾选授权后才会把当前数据放入API请求；模型本身、需求和版本摘要仍会发送。任何外部服务都应符合项目数据使用授权。

修改期间可以取消请求。需求或模型版本改变后，旧请求返回不会覆盖当前任务。

## 四、审核与修正

“确认本项”是人工审核记录，不是物理检验。把每条条件关联到一个或多个模型元素，便于追溯遗漏。代码可以复制或下载，但网页从不执行生成代码。

静态检查只覆盖定义的有限规则。有问题时填写修正要求，“携带问题请求修订”将当前模型、确认条件、人工备注、静态发现和外部复核报告送到模型API。返回形成新版本，再次确认。

“调用复核模型”是独立模型建议；“专业校验服务”是外部专业算法结果，分别保留引擎、证据和来源。后者须遵循接口契约，不是任意JSON都能直接接受。

Python语法按钮调用标准库ast.parse，不执行代码。MATLAB/MATPOWER没有解析器时显示未执行。

## 五、数据与风险

数据JSON/CSV先进入编辑区，再预检、确认绑定。示例四节点数据只复用原题给出的数值，不补造阻抗、初始状态、时长或成本计费口径。测点映射需要真实设备ID、单位和时标。

风险服务返回必须带task_id、model_version、model_hash、requirements_revision、data_fingerprint，全部匹配后才能纳入当前任务。建议接受并不是直接执行：候选新版本还需同步总体表达与代码。

Reward各项填写指标、方向、权重和归一化依据。它是设计契约而非训练结果。模型变化后须重新确认设计。发送后需对应版本的receipt_id回执。

## 六、保存和恢复

默认工作区在当前页面内存，刷新可能丢失。点击顶部“保存”写入本浏览器；“导出工作包”得到JSON。工作包可能包含业务数据，请保管好。密钥不进入工作包。

恢复或导入会重置审批、报告和当前风险，以免把旧结果当成本次已审核；历史模型原有输入版本信息继续保留。浏览器日志不是不可篡改审计。

## 七、地图

参考行政边界与电气拓扑分开。可以缩放、空白处拖拽平移、点击区域或节点。只有明确提供坐标并声明与底图一致的坐标系，设备才会叠加。不会猜测真实大理站点位置。

大量节点时展示上限为2000节点/5000支路，完整数据仍保存在任务中。自动圆形拓扑只是连接布局，不是地理坐标。
